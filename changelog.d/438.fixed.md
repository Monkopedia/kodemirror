- Fixed `:lsp-client` rename placing its edits wrongly when the user typed during the request
  (#438). The server's positions were read against the current document and then mapped through
  the edits since, so those edits counted twice, and an edit past the request-time document's end
  threw and dropped the whole rename. Each open file's positions are now read against that file's
  document at request time and mapped once, as `@codemirror/lsp-client` 6.3.1 does, including
  other open files the rename touches. As upstream, an edit the user touched is still applied.
