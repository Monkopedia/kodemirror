- `:language` language-data API (#449):
  - `Language` gains a `data` facet parameter and property, and its `extension` provides the data
    attached to the tree's top node.
  - `LRLanguage.define` takes `parser: LRParser` (was `Parser`) and an optional `languageData` map.
    It attaches the language's data facet to the parser's top node type.
  - `defineLanguageFacet(baseData: Map<String, Any?>?)` now returns a
    `Facet<Map<String, Any?>, List<Map<String, Any?>>>` (`LanguageDataFacet`). Values added with
    `language.data.of(...)` come before the base data, as upstream.
  - `LRLanguage` is constructed from an `LRParser`, and gains `configure(config, name)`, which
    keeps the language's data facet (as upstream). The Vue, Angular, Liquid and Jinja wrappers use
    it, so they publish their base language's data.
  - `:language` now exposes `:lezer-lr` as an API dependency.
  - Callers passing a non-`LRParser` to `LRLanguage.define`, or using the old
    `List<Extension>`-typed facet, must update.
