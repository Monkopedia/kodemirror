- `:autocomplete` now queries completion sources the way `@codemirror/autocomplete` 6.20.1 does
  (#422). Each source has at most one query in flight: edits made while it runs are replayed onto
  its result when it arrives, which then stays, is asked for again (keeping the session's
  explicit flag), or closes, so a slow source is no longer sent one request per keystroke. Only
  typing (`input.type`) opens completion; a paste, drop or other input no longer does. When an
  edit invalidates one source's result in a multi-source session, only that source is asked
  again. `asyncOverride` sources are queried alongside `override` ones and their options merged,
  rather than only when the sync sources return nothing. `selectOnOpen = false` is honoured.
- What callers may notice: queries run in the completion view plugin, so `startCompletion` on an
  `EditorSession` that isn't mounted in a `KodeMirror` composable no longer runs the sources.
  `completionStatus` returns `"pending"` while a source is being queried, and while one is, the
  list stays on screen but disabled: `currentCompletions` is empty and `acceptCompletion` does
  nothing until the source answers.
