- Fixed `:language`'s folding, bracket-matching and indentation helpers diverging from
  `@codemirror/language` 6.12.2 (#450), each established by running the same input through the npm
  package:
  - Folding a range that starts before an existing fold, or folding the same range twice, no longer
    throws `IllegalStateException: Ranges must be added sorted`. `unfoldEffect` removes only the
    exact range (nested folds survive), and a deletion inside a fold or a selection head moving into
    one clears it.
  - `foldable` returns the outermost foldable range starting on the line (`x = [{` folds the `[`,
    not the `{`). `foldCode`, `unfoldCode` and `toggleFold` act on every selected line;
    `unfoldCode` unfolds a fold starting anywhere on the line, `toggleFold` on an inner line folds
    the enclosing block, `foldAll` folds only top-level ranges, and the commands install
    `codeFolding()` when it is missing.
  - `matchBrackets` honours `dir` (`dir < 0` is the bracket ending at `pos`), reads
    `BracketMatchingConfig.brackets`, and reports mismatched pairs such as `([)]` as unmatched.
    `cursorMatchingBracket`/`selectMatchingBracket` follow upstream's lookup order.
  - `flatIndent` returns the node's base indentation instead of 0 (labeled statements in
    JavaScript, C++ and Go). `indentRange` empties whitespace-only lines. `getIndentation` without a
    language returns 0 at position 0. `StringStream.eatSpace`/`indentation` treat all of
    JavaScript's `\s` as whitespace.
