- Completion options are now ranked and filtered as `@codemirror/autocomplete` 6.20.1 does
  (#392). This changes which completions users see and in what order. The port's own scorer is
  replaced by upstream's `FuzzyMatcher`: a single typed character matches only at the start of a
  label, so `e` no longer offers every label containing an `e`. Word starts (`gbcr` for
  `getBoundingClientRect`), case folding and gaps are scored as upstream scores them, and the
  matched ranges are highlighted to match. The list is assembled as upstream's `sortOptions`
  does. Options are deduplicated only when label, detail, type, apply and boost all match, so the
  JavaScript `for` snippets no longer collapse into one, and the copy with the most information is
  kept. A `filter = false` result keeps its source order at the top. Sections sort by rank, and
  ties are broken by a locale-aware comparison of `sortText ?: label`. A differential against the
  npm package agreed on 60,248 of 60,249 query/label pairs and on all 400 generated multi-source
  sort scenarios. The one difference was a probe-encoding artifact from a lone surrogate.
- **API change:** `CompletionSection(name, rank: Int = 0)` is now
  `CompletionSection(name, rank: Int? = null, dynamicRank: Boolean = false)`, as upstream's
  `rank?: number | "dynamic"`. A section without a rank now sorts after every ranked section,
  ordered by name. Before, it was treated as rank 0. Callers that relied on the default rank 0
  must pass `rank = 0`. `dynamicRank = true` ranks a section by its best-matching option.
